# AGATA Core for GPoint

This is the channel-neutral Python dialogue, character/personality and memory core. It is a separate process from the TypeScript GPoint API and connects to the existing GPoint PostgreSQL database using only the `agata` schema. The old AGATA database and its data are not migrated.

## Local configuration

Use the `agata` profile in `infra/docker/docker-compose.yml`. Provide the `AGATA_*` settings in a local, untracked `.env`; generate independent random keys for message encryption and each HMAC domain. Do not copy the old AGATA `.env` or reuse its credentials. The development API is bound to `127.0.0.1:8001`; it is not bound to a public interface.

Required settings are `AGATA_DATABASE_URL`, `AGATA_TENANT_ID`, `AGATA_INTERNAL_API_TOKEN`, `AGATA_MESSAGE_AEAD_KEY`, `AGATA_REQUEST_FINGERPRINT_HMAC_KEY`, `AGATA_RETRIEVAL_QUERY_HMAC_KEY`, `AGATA_RESPONSE_FINGERPRINT_HMAC_KEY`, and `AGATA_SHADOW_CANDIDATE_HMAC_KEY`. Key values are base64-encoded; the AEAD key must decode to 32 bytes and HMAC keys to at least 32 bytes. A provider API key is needed only when a separately selected external provider requires one; neither `disabled` nor `mac_worker` requires an API key.

Apply only this service's Alembic migrations explicitly with `alembic upgrade head`; GPoint Prisma migrations do not own this schema. Revision `agata0001` creates the forced tenant-RLS schema, installs `vector`/`pgcrypto` only if absent, and seeds the configured tenant and conservative global policy. Revision `agata0002` encrypts legacy memory/summary/view payloads in place and replaces plaintext search terms with keyed opaque tokens. Revision `agata0003` backfills first-class relationship ownership and enforces tuple consistency through composite constraints. Revision `agata0004` installs encrypted relationship-owned memory snapshots; `agata0005` adds temporal-truth and exact-revision guards; `agata0006` adds the three forced-RLS persistent memory-graph projection tables without backfilling or copying plaintext. These revisions are intentionally irreversible; Alembic downgrade commands are disabled because no safe downgrade may expose plaintext or discard relationship ownership. Neither migration creates or alters GPoint tables. Never run them against production as part of this task.

Internal routes are authenticated with a service bearer token. `PUT /internal/v1/characters/{gpoint_character_id}` synchronizes immutable persona versions, `PUT /internal/v1/users/{gpoint_user_id}/consent` synchronizes a consent/age/disclosure snapshot, and `POST /internal/v1/respond` accepts one message and loads all history, persona, and memory within AGATA. The bounded Messages read routes are `GET /internal/v1/users/{gpoint_user_id}/chat-state`, `GET /internal/v1/users/{gpoint_user_id}/conversations`, and `GET /internal/v1/users/{gpoint_user_id}/characters/{gpoint_character_id}/messages`; they return only consent-authorized, owned `gpoint`/`real_world` data, decrypt inside AGATA, and never expose ciphertext, roleplay, or memory internals. Pagination is capped at 50 conversations and 100 messages (default 30 and 50). GPoint Creator IDs are the external AGATA Character IDs, and each user/creator pair uses the stable external conversation key `gpoint-chat:{userId}:{creatorId}`; AGATA's internal conversation UUID is not reused as that key. AGATA remains the sole dialogue/history store; no GPoint chat tables or AGATA migrations are added. The worker runs as `python -m app.memory.worker` and owns summary, extraction, promotion, and embedding outbox jobs.

Production Compose entries are behind the explicit `agata` profile. The canonical GPoint release flow builds and migrates the exact-SHA AGATA artifact, then starts and verifies it before switching the GPoint runtime. A provider may be explicitly configured as `disabled`; in that state health remains ready, no LLM credential or Mac worker is required, and message generation returns a controlled unavailable response after safely persisting the user message. API binds only to loopback in the local Compose file; readiness requires pgvector and the current Alembic head. The worker health check requires a recent content-free heartbeat and a reachable AGATA database.

Use `.env.example` only as a key-name/template reference. Generate independent random keys for each purpose, keep the real `.env` untracked, and do not rotate the AEAD/HMAC keys without a planned data re-encryption/re-index procedure. HMAC search tokens preserve token equality/frequency and support lexical matching; they do not reveal the original words, but still represent sensitive derived metadata.

## Temporary local Codex test provider

Shared worker V3 additionally requires a trusted `GPOINT_AGATA_TENANT_ID` pin
for its GPOINT runtime. An optional GSALES target requires independent
`GSALES_AGATA_WORKER_URL`, `GSALES_AGATA_WORKER_TOKEN`, and
`GSALES_AGATA_TENANT_ID` values. Keep both tenant pins in the mode-600 worker
configuration; never copy the production GPOINT pin into a disposable Core
runtime.

The owner-approved Unified Mac Worker V3 is an allowed production Codex inference provider for GPoint and G Sales. Provider selection remains configuration-driven: only `AGATA_LLM_PROVIDER=mac_worker` together with `AGATA_CODEX_LOCAL_ENABLED=true` selects the authenticated worker; the default remains `disabled`. This mode uses the existing worker gateway and the logged-in Codex CLI, with concurrency one, a bounded generation timeout, expiring durable inference jobs and a capped queue. Runtime health reports the G Sales provider degraded when authenticated worker polling is stale or the Core cannot prove its tenant security contract. It does not use an OpenAI API key or copy Codex/ChatGPT credentials to the VPS. When the bounded queue is full or the worker is unavailable, new messages fail closed with a controlled unavailable/pending response rather than causing uncontrolled work.

The local worker reads credentials from `~/.config/gpoint/agata-worker.env` (mode 600). Runtime code is sourced only from this repository and installed into `~/Library/Application Support/GPoint/agata-codex-worker/runtime/<source-sha>`; `runtime/current` points to the active immutable bundle. State, queues, receipts, logs, locks, and status live beside `runtime/`, outside source bundles. One LaunchAgent (`one.gpoint.agata-codex-worker`) runs the AGATA supervisor. GPOINT and GSALES are production lanes; LAB runs in the background only when production queues are empty and requires a valid, current approval immediately before inference. The default is one isolated process slot. Increasing concurrency is rejected unless provider parallel-safety has been explicitly verified; provider status remains `NOT_VERIFIED` until then. `run_codex_worker.sh` resolves the immutable bundle containing itself under the canonical Application Support runtime.

Use `python3 services/agata/worker/migrate_worker_runtime.py plan` for a read-only inventory and `prepare` to stage the exact candidate plus a verified rollback snapshot without stopping the LaunchAgent or changing `runtime/current`. The guarded `apply` action repeats the clean exact `origin/main`, idle, and release-lock checks, freezes the installed LaunchAgent, refreshes the rollback snapshot, then switches and verifies the new process, lanes, and successful polling. The old flat worker files share the canonical Application Support root with persistent state, so they are retained for rollback; only the active LaunchAgent moves to `runtime/current`. `rollback` restores the snapshot and original LaunchAgent plist. Failed health or restart checks automatically restore the previous service. The migration controller does not call VPS, database, MAXIBOT, or network-configuration tools.

## Natural Conversation MVP — Naturalness Policy V1

The versioned, opt-in treatment is `agata-naturalness-v1` (V1). It reuses the frozen candidate policy and positive synthetic examples from [AGATA Naturalness V1](https://github.com/akhripunov/gpoint/pull/14), pinned to source commit `e4b843d7ddaed1f96a8d24e8a186712b2e371896`. The source SHA-256 values are `b68d51e29b8611a053ac50bc89806bc8f1903f476126e155a7dc331927d94a6e` for the policy and `dcef7702d08657d3bc1ab50cc2670f4d99a21de321cb1c614e1472da98a889d6` for the examples. At runtime only the candidate-visible policy section and the 15 positive example turns are sent; evaluator-only anti-patterns and rationales are filtered out. Asset hash or schema mismatch fails closed.

GPoint's `POST /messages/creator/:creatorId` calls AGATA only when `AGATA_ENABLED=true` and the integration credentials are present. AGATA itself still defaults to `AGATA_LLM_PROVIDER=disabled`; otherwise its existing configured AnyModel or Mac Worker provider runs the same response orchestrator. The local source establishes this conditional route, but does not establish current production or staging environment values. No runtime read or deploy was performed for this task.

The switch is `AGATA_NATURALNESS_POLICY_ENABLED`, default `false`. Set it to `true` to add V1 policy and examples to either existing generation provider. Return it to `false` and restart the AGATA API process to restore the baseline prompt; this uses no database change or migration. If AGATA or its provider is disabled, the switch has no effect. The policy is appended as a shared conversational layer while the selected character's Persona, boundaries, safety instructions, and post-generation guards remain in force.

The response context continues to be assembled by the existing AGATA pipeline: versioned character profile, bounded recent history, relationship snapshots, conversation summaries, consent-filtered retrieved memories, and user communication settings. The Mac Worker adapter now also forwards the already-bounded public backstory, language/initiative/roleplay settings, and current dialogue summary that it previously omitted. No new memory source or database field was added.

### A/B preparation and evidence

Baseline is the current prompt with the switch off. Candidate uses the same provider, model, Persona, bounded context, user turns, and provider settings; the only treatment is Naturalness V1 policy plus its approved positive examples. The prepared pack reuses 16 existing DEV (`-02`) multi-turn scenarios from `worker/lab_fixture_manifest.json`: everyday chat, humor, support, user boundaries, persona consistency, initiative, topic changes, return after a pause, memory recall/correction, disagreement, advice requests, and one 12-turn continuity case. The compromised/sealed `-01` scenarios are excluded.

No new model calls were made. The local regressions verify prompt parity and fixture scope, not conversation quality. Linear's [AGATA Conversation Lab Handoff](https://linear.app/bestuzhev/document/agata-conversation-lab-handoff-31d9a8fed563) records an earlier real blind V1 smoke: 8/8 calls succeeded across four turns per arm on `gpt-6-luna / medium`, and the owner preferred Candidate Y on all eight reported dimensions. It is a promising directional result from one scenario, not evidence of broad improvement and not a result of this 16-scenario pack. New live comparisons remain unverified until a valid bounded inference authorization exists.
