## Architecture

G Sales is an independent FastAPI service, six CRM tables in `gsales`, separate
dependencies/image/entrypoint. It calls the same AGATA HTTP contract using a
separate GSALES runtime, tenant UUID, token, encryption keys and login role.
AGATA runtime source discriminator defaults to gpoint for compatibility.
The tenant identity is bound to session_user, not a caller-controlled GUC.
AGATA owns all messages/personas/memory; CRM stores hashes/references and
delivery/approval state. Draft content stays in AGATA protected storage.

## Review focus

- A fresh approval must bind content/recipient/seller/account atomically.
- A crash after Telegram dispatch must leave unknown, never an automatic retry.
- Owner takeover and opt-out must be checked at the final serialized send gate.
- A changed username must not redirect approved stable Telegram user ID.
- SET tenant, SET ROLE, table ownership and security-definer search_path cannot
  permit cross-tenant SQL. App roles cannot create/control their bindings.
- No invented consent, registration, product claims, or network tests on users.
