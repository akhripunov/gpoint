# GPoint: отсутствие ответов и сбой финализации релиза, 2026-10-01

## Причины

1. AGATA работала с `AGATA_LLM_MODEL=codex-default`, а существующий включённый маршрут Models Hub ссылался на `cx/gpt-5.6-terra`. `sync_character` искал любой включённый маршрут профиля. Он возвращал 200, не создавая маршрут текущего provider/model. Следующий `/respond` сохранял пользовательское сообщение, затем возвращал 503 до создания inference job.
2. В конфиге Mac worker было `AGATA_CODEX_MODEL=`. Запуск CLI правильно трактовал пустое значение как модель по умолчанию, но запрос `/worker/complete` передавал `model=""`. Сервер требует непустую строку: зафиксирован HTTP 422. Через шлюз эта ошибка выглядела как временный сбой, worker продолжал heartbeat, а задача оставалась leased до истечения TTL.
3. Команда `POST_RELEASE_CLEANUP` разрасталась примерно до 270 КБ. Передача команды аргументом SSH завершалась exit 255 после успешного переключения runtime. Точная команда, переданная файлом и проверенная по SHA256, завершилась успешно. Это подтверждает пригодность передачи через файл; внутренняя причина отказа sshd отдельно не установлена.

## Исправления

- `ce38486ef416869e217c5fa41773c02f258d38e0`: синхронизация неизменённого профиля проверяет весь настроенный tuple provider/model/prompt/schema/policy. Старый маршрут больше не подавляет создание текущего. Явно отключённый оператором точный маршрут сохраняется отключённым; дубликат не создаётся.
- `62d96acc67bd739599b7edf205e5fabeed6456ce`: worker нормализует пустую/пробельную модель в `codex-default` при сохранении результата. Локальный установленный файл сверяется по SHA256 с опубликованным исходником.
- В том же SHA: команды очистки длиннее 32768 байт передаются защищённым файлом; SHA256 проверяется перед выполнением. План удаления, защита current/rollback и обработка ошибок сохраняются.

## Проверки и границы подтверждения

- 64 теста AGATA прошли; 24 теста PostgreSQL пропущены из-за отсутствия локальной тестовой БД.
- 83 теста релизного инструмента прошли. Новые проверки включают реальные shell-проверки корректного и повреждённого переданного скрипта, а также сохранение ошибки выполнения.
- Реальный локальный запуск Codex на безличном запросе вернул структурированный ответ.
- Повторная обработка уже сохранённого сообщения с прежним idempotency key после исправления маршрута вернула 200 pending и создала inference job без дублирования сообщения. До установки исправленного worker сохранение результата получило 422, затем задача истекла (`inference_job_expired`). Терминальная задача не сбрасывалась вручную.
- Ошибка bootstrap LaunchAgent после остановки старого процесса устранена повторной регистрацией корректного plist; процесс GPoint worker запущен.
- Heartbeat и `/health/live` подтверждают доступность, но не прохождение пользовательского сообщения. Для окончательного smoke нужен новый запрос, inference completed, response_retry completed и сохранённый assistant message.

## Оставшиеся системные ограничения

- Полного Docker/DB rehearsal candidate в dry-run и CI по-прежнему нет.
- Текущее состояние worker может скрывать прошлую ошибку и показывать устаревший `current_job_present`; heartbeat нельзя использовать как критерий работоспособности ответа.
- На production обнаружены `memory_extract: extractor_unavailable` и повторяющаяся `relationship_note_refresh`. Этот инцидент не доказывает исправность извлечения/обновления памяти.
- Генерация через Mac worker зависит от включённого Mac, сети и доступности CLI. Эти изменения исправляют найденные ошибки, но не гарантируют отсутствие всех будущих инфраструктурных сбоев.
